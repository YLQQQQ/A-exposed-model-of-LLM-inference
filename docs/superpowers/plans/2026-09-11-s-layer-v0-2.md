# S 层 v0.2 实施计划

> **执行要求：** 逐任务测试先行；每个任务结束复核 completion semantics 和 fail-closed，并提交独立检查点。

**目标：** 完成 Gate 4。S 层只读取 Canonical Raw v0.2，根据同步 registry、提交证据、request ownership、同流/event/default-stream 依赖恢复每个 Host blocking sync 的 `W(s)`，再给出 terminal 与 validity。

**核心边界：** 时间重叠只用于测量已确认依赖的暴露区间，永远不产生依赖边。S 不计算 A/B；历史 trace 因旧 NVTX identity 保持不可用于强归因。

## 任务 1：Canonical bundle 加载与 registry 分类

**文件：**新建 `exposedpath_v141/sync_semantics.py`、`tests/test_v141_sync_semantics.py`。

- [ ] 先写 bundle schema/hash 不匹配、API ABI 后缀归一化、Host blocking / dependency edge / query / unsupported / unknown 分类测试。
- [ ] 实现只读 gzip JSONL loader，逐文件验证 SHA-256、记录数和 schema 版本。
- [ ] 用 `sync_semantics_registry_v0_2.json` 分类 runtime API；保留原 API 名称和 registry rule，不以 CUPTI syncType 标签替代分类。
- [ ] 定向测试通过并提交。

## 任务 2：冻结 ownership 与 submission evidence

- [ ] 先写 CUDA API correlation、结构化 phase 包含关系、manifest/NVTX 冲突、缺 request identity、跨 invocation bleed 测试。
- [ ] activity ownership 只来自唯一 correlated enqueue API 所在的结构化 request/phase；sync ownership只来自其唯一 runtime API 所在范围。
- [ ] submission 只接受 `gpu_start < sync.host_start` 或 `enqueue.host_end <= sync.host_start`；仅 correlation 或 enqueue start 不足。
- [ ] 保存 activity origin phase、sync owner phase 和 cross-phase 候选；不因 phase 不同删除合法依赖。
- [ ] 定向测试通过并提交。

## 任务 3：构造语义依赖图并恢复 W(s)

- [ ] 先写 stream、device、context、event record 前缀、cross-stream wait-event、completed-before、无关重叠和 default legacy/PTDS 测试。
- [ ] 构造 SAME_STREAM_ORDER、EVENT_RECORD_CAPTURE、STREAM_WAIT_EVENT 与受支持 default-stream 边；边只来自可观察顺序事实。
- [ ] stream sync 取目标流提交前缀及传递前驱；device/context 取相应 scope 的已提交、同请求活动；event sync 取调用时可见的最新 event record 捕获前缀。
- [ ] default stream 被观察但 mode 缺失时 ambiguous；legacy nonblocking stream 例外由 stream flag 保留。
- [ ] 证明 completed-before 仍在 W，跨流时间重叠但无边不进入 W。
- [ ] 定向测试通过并提交。

## 任务 4：terminal、validity、输出与 Gate 4 审查

- [ ] 先写 semantic frontier 唯一、多 frontier 唯一最晚、0 ns tie、terminal after sync、valid-empty、原因优先级和 Q0 expected 对照测试。
- [ ] terminal 先由语义 frontier 决定；多个 frontier 仅在共享时钟域存在唯一最晚完成时选择，等时为 `TERMINAL_TIE/AMBIGUOUS`。
- [ ] 输出每个 Host blocking sync 的稳定身份、completion scope、submission/closure、W、terminal、ownership、cross-phase、validity 与原因；不输出 A/B 数值。
- [ ] 建立 `analyze-s` CLI 与版本化 S bundle；输入 identity/observation 非 valid 时按合同传播或拒绝强归因。
- [ ] 写中文 S 层说明并更新科研进度；运行定向、oracle 对照、下游边界、全量测试，只允许两项既有 PowerShell smoke 失败。
- [ ] 提交 Gate 4。

## 完成后的下一 Gate

Gate 4 通过后进入 Gate 5：A 只使用 S 的 validity 与 `W(s)` 对 request/phase 墙钟做互斥守恒记账；B 只对单个有效同步解释 hidden/exposed/return-tail，禁止跨同步求和。
