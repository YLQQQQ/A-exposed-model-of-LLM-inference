# ExposedPath 文档整合与修订计划

## 1. 本轮目标

在不覆盖任何历史文档、不改变当前代码、不提前冻结实验协议的前提下，将现有研究材料整合成两份可继续评审的中文版候选文档：

1. `研究设计主体 v7.0 Pre-Pilot 整合候选版`：回答研究问题、方法语义、证据链、贡献边界和当前阶段。
2. `实验与分析协议 v2.1 Pre-Pilot 整合候选版`：回答如何分阶段验证、采集、分析和决定是否进入正式实验。

本轮属于研究文档整理，不代表 Measurement Contract、Q0、Pilot 或 Protocol Freeze 已通过。

## 2. 权威层级

| 层级 | 材料 | 本轮角色 |
|---|---|---|
| 当前约束 | v1.4.1 补充说明、用户已确认的研究边界、仓库 `AGENTS.md` | 约束本轮修订；发生冲突时优先 |
| 主体底稿 | 研究设计与论文证据框架 v6.0 | 保留有价值的背景、定位、方法骨架和证据—主张关系 |

在用户审阅并完成 Gate 1 语义审查前，v1.4.1 仍是当前权威研究方案，两份新文档均标记为“候选版”。

## 3. 已确认的关键修订

- 将 `W(s)` 定义为同步完成语义确定的请求内前驱活动集合，不能只选“同步开始时仍未完成”的活动；同步前已完成但属于 completion scope 的活动仍在集合中。
- `valid_empty` 仅表示没有请求内、可归属的前驱活动，不能表示“前驱已经提前完成”。
- terminal 必须由完成语义、事件关联和唯一性证据确定；不能只取时间戳最大活动。证据不足、并列不可判或 ownership 不清时必须标记 `ambiguous/invalid`。
- 时间重叠只能是观测事实，不能独立证明 dependency。
- 自然逐 Token 同步属于纯模型流式推理的 Token 就绪边界；Token 转文本、网络传输、前端显示和外部消费者处理不属于核心测量范围。
- A 是 request/phase 内互斥、保守的 wall-clock accounting；B 保留 per-sync provenance，默认不得跨同步相加；D 只用于导航；Exposure Signature 是 A/B 的派生机制摘要。
- 主证据链固定为 `Correctness -> Information Gain -> Decision Gain`，对应 Q0、N1/G1、G2。
- G1 允许比例变化、非比例变化、分区依赖或 null 结果；不得把“必须出现迁移”写成成功条件。
- G2 只有在冻结规则和 held-out 场景下证明增量决策价值时才支持相应主张。

## 4. 执行顺序与验收

| 步骤 | 操作 | 完成条件 |
|---|---|---|
| 1 | 固定四份输入材料的路径、版本、哈希和角色 | 来源可追溯，WMPC v1.5 与协议 v2.0 不再混淆 |
| 2 | 生成研究设计主体候选版 | 核心问题、范围、Raw→S→A/B→D/Signature、Q0/N1/G1/G2 和 claim 边界一致 |
| 3 | 生成实验协议候选版 | 数据角色、Gate 顺序、Q0 oracle、自然/人为同步、Pilot 决策项和冻结条件一致 |
| 4 | 生成 DOCX 并做结构检查 | 文件可解压、可由 `python-docx` 读取，标题/章节/表格和关键术语齐全，无占位符 |
| 5 | 做页面渲染检查 | 无截断、重叠、越界和不可读表格；若本机缺渲染器则明确记为 `BLOCKED` |
| 6 | 更新唯一科研进度清单 | 新增任务、证据和阻塞状态；最高优先级仍指向 Measurement Contract |
| 7 | 用户审阅后决定升级 | 只有用户确认且 Gate 1 通过后，才更新权威层级或进入正式协议冻结流程 |

## 5. 不在本轮范围内

- 不修改 benchmark、runner、parser 或 analyzer 代码。
- 不把历史 trace 升格为 Q0、Pilot 或 Formal 证据。
- 不确定正式 GPU、固定 repeat 数、开销阈值或最终 workload matrix。
- 不扩大到多 GPU、分布式 serving、并发请求 ownership、硬件因果归因或通用性能预测。
- 不删除、覆盖或重命名任何原始 DOCX。
